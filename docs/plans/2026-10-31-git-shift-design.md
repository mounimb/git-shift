# git-shift — Design

- **Date:** 2026-10-31
- **Status:** Approved
- **Author:** Mounaim Belkhoumali (@mounimb)

## Problem

I use several GitHub accounts on the same Windows machine. Git has one global
identity, so it is easy to commit to a repository with the wrong email. GitHub
then credits the commit to the wrong account, and the mistake is only visible
after pushing. On my own `mounimb` repositories, 5 commits are currently
attributed to my other account because my global `user.email` belongs to it.
The `gh` CLI adds a second layer: the active `gh` account can also be the wrong
one, and expired `gh` logins go unnoticed.

## Goal

`git-shift` is a small, dependency-free Python CLI that maps folders to git
identities (name, email, SSH key, `gh` account), explains which identity applies
in any directory, and blocks commits and pushes made with the wrong identity.

It is used as a git subcommand: the executable is named `git-shift`, so git runs
it as `git shift ...`.

### Non-goals (v0.1)

- Storing or managing tokens or passwords.
- Rewriting existing history.
- Automatic `gh` account switching (roadmap).

## Approach

Three approaches were considered:

1. **Git-native conditional includes (chosen).** Manage `includeIf "gitdir/i:..."`
   rules in the global git config, each pointing at one identity file. Works in
   every git client (terminal, VS Code, GitHub Desktop, IDEs) even when
   `git-shift` is not running, because it is plain git configuration.
2. **Per-repository config.** Write `user.email` into each repo's `.git/config`.
   Simple, but relies on remembering it for every clone. Kept only as the
   one-off `use --here` command.
3. **Wrapping the `git` command.** Inject identity flags through a shell
   wrapper. Breaks GUI clients and is fragile on Windows. Rejected.

A guard (global `pre-commit` and `pre-push` hooks) is added on top of approach 1.

## Commands (v0.1)

| Command | Purpose |
|---|---|
| `git shift add <name> --email E --name N --folder DIR [--ssh-key PATH] [--gh LOGIN]` | Create an identity and bind it to a folder |
| `git shift list` | List identities and their folders |
| `git shift status` | Show which identity applies in the current directory, why, and the effective email, SSH key and `gh` account |
| `git shift remove <name>` | Delete an identity and its include rule |
| `git shift use <name> --here` | Pin an identity on the current repository only; the pin beats the folder and remote rules |
| `git shift doctor [--fix]` | Health checks (see Error handling). `--fix` only rewrites `rules.gitconfig` from the identity files |
| `git shift guard install` / `uninstall` | Install or remove the commit/push guard |

Global flag: `--debug` prints tracebacks for unexpected errors.

## Architecture

### Principle: git is the source of truth

`git-shift` never parses or edits `~/.gitconfig` by hand. All reads and writes go
through `git config` (`--global`, `--file`, `--show-origin`). What `status`
reports is therefore exactly what git does.

### Files on disk

```
$XDG_CONFIG_HOME/git-shift/          (default: ~/.config/git-shift/)
    identities/
        perso.gitconfig
        pro.gitconfig
    rules.gitconfig                  (includeIf rules, fully owned and regenerated by git-shift)
    hooks/
        pre-commit, pre-push         (guard + chain)
        commit-msg, post-checkout... (chain only)
        _git_shift_launch.py         (hook launcher)
    backups/
        gitconfig-<timestamp>
    state.gitconfig                  (previous global core.hooksPath)
```

An identity file is a regular git config file:

```ini
[user]
    name = Mounaim Belkhoumali
    email = me@example.com
[core]
    sshCommand = ssh -i ~/.ssh/id_perso -o IdentitiesOnly=yes
[gitshift]
    folder = C:/Users/me/code/perso/
    gh = mounimb
```

The `[gitshift]` section holds metadata git ignores. There is no separate
database: one file per identity is the single source of truth.

`rules.gitconfig` holds one rule per identity and is regenerated entirely on
every change:

```ini
# Managed by git-shift. Do not edit by hand.
[includeIf "gitdir/i:C:/Users/me/code/perso/"]
    path = C:/Users/me/.config/git-shift/identities/perso.gitconfig
```

The global config receives a single line, added once with
`git config --global --add include.path`:

```ini
[include]
    path = C:/Users/me/.config/git-shift/rules.gitconfig
```

`git-shift` never modifies any other entry of the global config.

### Path handling

- Paths are written with forward slashes on every platform.
- Folders are stored as absolute, symlink-resolved paths, because git matches
  the resolved `.git` path first and `~` differs between Windows shells.
- `gitdir/i:` (case-insensitive) is used so rules match on Windows and macOS.
- A trailing `/` is always added, so the rule covers all subfolders.
- Glob characters in folder names (`[`, `*`, `?`, `\`) are escaped in the
  `includeIf` key, because git matches `gitdir` patterns with wildmatch. The
  stored folder stays literal.
- `status`, `doctor` and the guard match folders against the repository's git directory,
  as `gitdir` does, so a worktree follows the folder of its main clone.

### Rule ordering

Git applies every matching include in file order; the last one wins. Nested
folders are allowed (for example `~/code/` = perso and `~/code/pro/` = pro).
`rules.gitconfig` is written with rules sorted by folder depth, so the most
specific folder always wins.

### Modules

```
src/git_shift/
    __init__.py
    __main__.py     python -m git_shift
    cli.py          argparse parser, subcommands, output formatting, exit codes
    errors.py       GitShiftError: expected errors shown without a traceback (exit 2)
    paths.py        config locations, path normalisation, folder matching
    gitconfig.py    thin subprocess wrapper around `git config`
    store.py        Identity dataclass; create/list/remove identities and include rules
    resolve.py      which identity applies in a directory, and why
    doctor.py       health checks
    guard.py        hook installation and the commit/push checks
    gh.py           read-only wrapper around `gh auth status`
    remotes.py      parse remote URLs (https and scp-like SSH) into host/owner/repo
```

### Data flow: `add`

1. Validate name, email, folder and SSH key.
2. Write `identities/<name>.gitconfig` via `git config --file`.
3. Regenerate `rules.gitconfig` in depth order.
4. If the global config does not include `rules.gitconfig` yet, back it up
   (first change only) and add the include.
5. Print the folder and email, plus warnings (missing folder or SSH key).

### Data flow: `status`

1. Ask git for the effective `user.email`, `user.name` and `core.sshCommand`
   with `--show-origin`.
2. Map the origin file back to an identity, or report "global default",
   "repository-local override" or "none". `author.email` and `GIT_AUTHOR_EMAIL` beat
   `user.email` in git, so they are checked first, and each cause gets its own fix.
3. Read the expected `gh` login from the identity and compare it with the
   active `gh` account.

## Guard

### Installation

`git shift guard install` writes `pre-commit` and `pre-push` scripts into
`~/.config/git-shift/hooks/` and sets the global `core.hooksPath` to that
directory.

- A global `core.hooksPath` disables repositories' own `.git/hooks`. After its
  check, each guard script runs the repository's own hook of the same name if
  it exists and is executable.
- Because the global setting disables every local hook type, pass-through
  scripts (chain only, no check) are installed for the other client hooks
  (`commit-msg`, `prepare-commit-msg`, `post-checkout`, `post-merge`, ...) and
  for `pre-receive` and `post-receive`, so pushes into a local repository still
  run its hooks. Left out:
  - `reference-transaction` and `post-index-change` run on almost every git
    command, and `update` once per pushed ref: a shell start per call would slow
    git down;
  - `post-update` gets every pushed ref on its command line;
  - `push-to-checkout` would replace the built-in `updateInstead` worktree
    update just by existing;
  - `proc-receive` and the git-p4 hooks serve review servers and the Perforce
    bridge only.
- Every script first counts how deeply git-shift hooks are nested
  (`GIT_SHIFT_DEPTH`) and skips its work past 5, so a `core.hooksPath` that
  loops back to the guard cannot hang git. `install` also refuses to chain to a
  directory that holds git-shift hooks.
- If a global `core.hooksPath` already exists, its value is saved in
  `state.gitconfig` and hooks chain to that directory instead. `uninstall`
  restores it in one write and removes only git-shift's own value. Without a
  global value, hooks chain to the system `core.hooksPath`, which is not saved
  because removing the guard brings it back by itself.
- `core.hooksPath` is read with `[include]` files, from a directory outside any
  repository, so an `[includeIf]` that applies only to some folders never
  passes for the global value. `install` warns when an include read after
  git-shift's value overrides it.
- Hooks call `<python> -I _git_shift_launch.py`. The interpreter path is
  recorded at install time, so hooks work when `git-shift` is not on `PATH`
  (for example inside a virtualenv). Isolated mode (`-I`) keeps the repository
  directory off `sys.path`, so a repository can never shadow the `git_shift`
  package; the launcher adds the installed package location explicitly.
- Hook scripts are POSIX `sh`, written with LF line endings, which Git for
  Windows runs through its bundled shell.

### Rules

| Hook | Rule |
|---|---|
| `pre-commit` | If the repository is pinned with `use --here`, or else inside an identity's folder, the author email git will record must equal that identity's email. |
| `pre-commit` | If the repository is outside every folder but its `origin` owner matches an identity's `gh` login, that identity's email is required. |
| `pre-push` | Every commit being pushed (from the ranges git passes on stdin) must have the expected author email. |

Blocked output:

```
✗ git-shift: this repo belongs to "perso" (jane), but you are committing as jane@company.com
  expected: jane@example.com  (matched by folder /home/jane/code/perso/)
  fix:      git shift use perso --here
  why:      git shift status shows where the wrong email comes from
  amend:    your own commit: add --reset-author; someone else's: --no-verify
  --author: drop it
  bypass:   git commit --no-verify
```

`use --here` fixes a wrong `user.email`, but not `GIT_AUTHOR_EMAIL`,
`author.email`, `--author` or the old author kept by `--amend`. `status`
names the cause; the hook alone cannot tell them apart.

### Failure policy

If `git-shift` itself fails inside a hook (a bug, a malformed identity file,
git refusing to work in the repository), the hook prints a warning and exits
0. A bug in the tool must never block every commit on the machine:

```
git-shift: warning: guard skipped after an error:
  <the error, one indented line per line>
```

Only exit code 3 blocks. A missing Python or launcher skips the check with a
warning, and the repository's own hooks still run.

## `gh` integration (v0.1, read-only)

- Read the active account and login validity by parsing the text output of
  `gh auth status` (the multi-account format of gh 2.40+ and the older
  single-account format).
- `status` and `doctor` report the expected vs active account, invalid logins,
  and the exact fix command (`gh auth switch -u <login>`).
- If `gh` is not installed, these checks are skipped.

## Error handling

### Validation in `add`

- Invalid email, duplicate name, or a name outside `[a-z0-9_-]` is refused.
- A folder that does not exist yet is allowed with a warning.
- A missing SSH key file produces a warning.

### Checks in `doctor` and explanations in `status`

| Situation | Message |
|---|---|
| A repository-local `user.email` overrides the folder rule | "overridden by this repo's local config (.git/config)" |
| The default `[user]` block comes after `git-shift`'s rules in the global config | "your default config overrides git-shift rules" + fix |
| The repository sets its own `core.hooksPath` (husky, pre-commit), so the guard does not run | "guard inactive in this repo" |
| Identity folder or SSH key missing | warning / error |
| Invalid `gh` login | error + fix command |
| Git older than 2.13 (no `includeIf`) | error with the minimum version |
| `rules.gitconfig` differs from what the identity files would generate (hand edit, older version, folder resolving differently) | "rules.gitconfig is out of date" + fix `git shift doctor --fix` |

`status` and the guard never rewrite `rules.gitconfig`: they only read configuration, and a
hook must not change the global config during a commit.

### Safety

- The global config is backed up before the first change.
- Only `git-shift`'s own entries are ever modified or removed.
- `remove` deletes the identity and its rule, and `guard uninstall` removes the hooks and
  `core.hooksPath`. The single `include.path` line stays after the last identity is
  removed; it is harmless, and the README shows how to delete it by hand.

### Exit codes

- `0` success, also when `use --here` wrote the pin but warns that another email still wins
- `1` a check failed (`status` email mismatch, `doctor` problems, guard block), or an
  unexpected error
- `2` usage error, or an expected error such as a git command that failed, including git
  refusing to work in a repository (dubious ownership, unknown repository extension)
- `130` interrupted with Ctrl-C

Expected errors print a message without a traceback, including all git said when git refused;
`--debug` adds the traceback.

## Testing

- **pytest**, no network.
- **Unit tests:** path normalisation (Windows and POSIX), rule ordering, remote
  URL parsing (`https://github.com/o/r`, `git@github.com:o/r.git`,
  `ssh://git@github.com/o/r`), validation.
- **Integration tests with real git:** every test runs with a temporary `HOME`,
  `USERPROFILE` and `XDG_CONFIG_HOME`, and `GIT_CONFIG_NOSYSTEM=1`, so the
  developer's real config is never read or written. Tests create repositories
  inside identity folders, run real `git commit`, and assert the author email.
  Guard tests cover a blocked commit and a pre-push check against a local bare
  remote.
- **`gh`:** a fake `gh` executable on `PATH` returns canned output.
- **CI (GitHub Actions):** Ubuntu, Windows and macOS × Python 3.10 and 3.14,
  plus `ruff`.

## Packaging and release

- `pyproject.toml`, `src/` layout, build backend `hatchling` (build-time only).
- Zero runtime dependencies; Python 3.10+ (3.9 reached end of life in
  October 2025).
- Console script: `git-shift = git_shift.cli:main`.
- Tag `v0.1.0` → GitHub Release → PyPI via Trusted Publishing (no API token
  stored anywhere).
- Repository files: `README.md`, `LICENSE` (MIT), `CHANGELOG.md`, `ROADMAP.md`,
  `.gitignore`.

## Roadmap (post-v0.1)

- Match identities by remote URL (`includeIf "hasconfig:remote.*.url:..."`,
  git 2.36+) in addition to folders.
- `git shift fix`: correct the author of unpushed commits.
- `git shift ssh new <name>`: generate an SSH key and add it to GitHub via `gh`.
- Automatic `gh` account switching per folder.
- Per-identity commit signing (SSH or GPG).
- Import an existing setup from `~/.gitconfig` and `~/.ssh/config`.
- Recognise SSH host aliases (`git@github-work:...`) in the origin-owner check.
- Shell completion; Scoop and Homebrew packages.
